# GUI Research — Cross-Language Study & a Blazing-Fast Rust UI Redesign for `dumpster_fire_engine`

> **Purpose.** Mine the best GUI implementations across many languages for their
> architectural patterns, *prove* at the instruction level (godbolt + local
> `objdump`/`rustc --emit asm`) how their fast paths are built, and translate the
> lessons into a concrete redesign of this engine's UI that is both far more capable
> and faster than what we ship today.
>
> **Audience.** Engine contributors. Every recommendation names a real file and is
> backed by either a primary source or a reproducible assembly listing under
> [`docs/gui_research/asm/`](docs/gui_research/asm/).

## 1. Executive summary

The engine already made the single most important low-level decision correctly:
it replaced `Box<dyn LayoutSolver>` with an **inline `LayoutDispatch` enum** and
swapped widget callbacks for **bare `fn` pointers** (`src/render/ui_core/layout.rs`,
`widget.rs`). Section 4.1 proves this was worth it: in a hot loop the `dyn` version
emits a per-iteration `call qword ptr [rax+24]` plus register spills, while the enum
version stays a register-only branch-and-compute loop. **Keep doing this.**

What the survey and the assembly tell us to change:

| Theme | Lesson (who) | Evidence | Target file |
|---|---|---|---|
| **Don't allocate per widget per frame** | Clay resets one bump pointer/frame; Nuklear/ImGui never heap-allocate in the build loop. We `String::to_owned()` + `Signal::new()` *per widget per frame*. | §4.2: bump `reset` = one store; `alloc` = ~6 instrs no-call; `String` = `__rust_alloc`+memcpy | `ui_widgets/immediate.rs` |
| **Reactivity must not borrow-check on read** | Compose/SwiftUI compare a version/epoch; we deref `Rc<RefCell>` + check a borrow flag + branch to a panic path on *every* `Signal::get`. | §4.5: `Signal::get` ⇒ borrow-flag compare + `panic_already_mutably_borrowed`; epoch read ⇒ one `vmovss` | `ui_core/signal.rs` |
| **Cache layout, recompute only dirty subtrees** | Yoga/Flutter cache measurements and skip unchanged nodes; we have `dirty: u8` flags but the IM path rebuilds unconditionally. | §4.4: branchless flat layout vectorizes (`vaddps`, 8× unroll); branchy match stays scalar | `ui_core/layout.rs` |
| **Damage regions / retained scene** | Flutter `RepaintBoundary`, WebRender batches of 512, Qt Quick "3 draw calls" reorg. We re-tessellate and re-upload the whole drawlist every frame. | §4.3: AoS 20-byte vertex stride blocks cross-vertex SIMD | `ui_render/{drawlist,renderer}.rs` |
| **Separate the build tree from the render tree** | Flutter's Widget/Element/RenderObject; React's VDOM/Fiber; egui's Context→Shapes→Mesh. We mix build, state, layout, and draw in one pass. | §3 | whole `ui_core` + `ui_manager` |
| **One source of truth** | — | — | `ui_core` and `resource_manager/ui_manager` are *two parallel* widget/layout/draw stacks today |

The redesign (§6) proposes a **hybrid**: a retained layout/render tree with stable
IDs and cached, dirty-tracked layout, fronted by a thin immediate-mode build API
backed by a per-frame bump arena, with epoch-based reactivity and damage-driven
partial re-upload over the existing ring-buffered Vulkan drawlist.

## 2. Baseline: the engine's current UI

The engine has a **mature, fully homegrown UI — no external UI crate** (no egui,
iced, imgui-rs). It is, however, *two* parallel stacks that overlap heavily:

### 2a. `src/render/ui_core/` — retained widget tree
- `widget.rs`: `Widget { id, kind: WidgetKind, parent, children, dirty: u8, rect,
  constraint, layout_solver: LayoutDispatch, event_handlers: ThinVec<EventSink>,
  user_data }`. `WidgetKind` is a 10-variant enum (Label/Button/Slider/Checkbox/
  Dropdown/TextEdit/Panel/VirtualList/OutlinerTree/PropertyGrid).
- **Good idioms already present**: `LayoutDispatch` enum dispatch (no vtable);
  `VirtualListState.item_builder: fn(usize, f32)` and `PropertyDesc.{get,set}: fn(...)`
  are *bare fn pointers* (no `Box<dyn>`); `DropdownState.options: ThinVec<Arc<str>>`
  interns strings; `dirty: u8` bitflags (`LAYOUT|CONTENT|CHILDREN`) exist.
- `layout.rs`: `LayoutSolver` trait + `RowLayout`/`ColumnLayout`/`NullLayout`,
  unified behind `LayoutDispatch`. Two-phase `measure`/`arrange`. `LayoutContext`
  is a reusable `ThinVec<Option<Size>>` keyed by dense `WidgetId::idx`.
- `signal.rs`: `Signal<T> = Rc<RefCell<SignalInner<T>>>`; `get()` **clones** the
  value behind a runtime borrow. **`map()` is a stub** — it pushes a sentinel
  subscriber and never actually recomputes the derived signal (see its own comment).
- `event.rs`, `theme.rs` (Dark/Light), `id.rs` (generational `WidgetId`).

### 2b. `src/resource_manager/ui_manager/` — retained widgets + IM + fonts
- Per-widget files (`button.rs`, `slider.rs`, …), `panel.rs`, `layout.rs`
  (`Sizing::{Fill,Fixed,Hug}` flex distribution), `draw.rs` (`DrawList`, `UiVertex`),
  `font.rs` (static 8×16 VGA bitmap), `atlas.rs`, `input.rs` (`UiInputState`).

### 2c. Rendering — `src/render/ui_render/`
- `drawlist.rs`: `DrawList { vertices: ThinVec<UiVertex>, indices: ThinVec<u32> }`
  with `push_rect`/`push_line`/`push_text`.
- `vertex.rs`: `#[repr(C)] UiVertex { pos:[f32;2], uv:[f32;2], color:[u8;4] }`
  (**20-byte stride**), plus a `RingBuffer` (FRAMES_IN_FLIGHT = 3) of host-visible
  mapped buffers — geometry is re-uploaded every frame and the buffer rotated.
- `font.rs`: dynamic `fontdue` atlas with a sorted glyph cache.

### 2d. Immediate-mode builder — `src/render/ui_widgets/immediate.rs`
`UiBuilder::resolve_or_create` does, **per widget per frame**:
`WidgetIdPath(self.id_stack.clone()).to_string()` (a `String` alloc) and each helper
constructs `Signal::new(text.to_owned())` (more allocs) before checking whether the
widget already exists. This is the single biggest avoidable cost on the build path.

### 2e. Confirmed gaps
No per-widget **focus / keyboard navigation** (global hit-test only); no rendered
**multi-line TextEdit**; **no scroll containers** (`VirtualListState` exists but isn't
rendered); **no docking/windowing**; **no animation/transition** system; **reactive
graph is incomplete** (`Signal::map` is a stub).

### 2f. Bench surface to build on
`benches/ui_core.rs` already measures `LayoutContext::{set,get}_size`, `Signal::{get,
set,subscribe}`, `EventBus::emit+drain`, `Constraint::clamp` with criterion. Every
redesign phase in §7 should extend this file so regressions surface in the normal harness.

## 3. Cross-language survey

Each entry: *paradigm · data model · layout · paint · identity/state · text · the one
transferable lesson.* Grouped by the four families this study prioritises.

### 3.1 Immediate-mode (C++, Rust, C)

**Dear ImGui (C++).** The reference immediate-mode toolkit. The UI *is* the call
sequence; per-widget state lives in a hashed-ID storage keyed by an **ID stack**, and
the only output is an `ImDrawData` list of vertex/index buffers + clip rects. The
community's measured conclusion is that immediate mode is *not* inherently slower than
retained mode — choose on ergonomics, not perf
([IMGUI paradigm wiki](https://github.com/ocornut/imgui/wiki/About-the-IMGUI-paradigm),
[Proving IMGUIs are performant](https://www.forrestthewoods.com/blog/proving-immediate-mode-guis-are-performant/)).
**Lesson:** the ID-stack identity model and "build → draw list → backend" split are
exactly what our `UiBuilder` is reaching for; formalize the draw-data hand-off.

**egui (Rust).** Rebuilds every frame; `Context` is the single shared state (one
`RwLock`, accessed via closures like `ctx.input(|i| …)` to avoid double-lock
deadlocks). The pipeline is **build → `Shape`s → `epaint::Tessellator` → `Mesh`
(vertices+indices)**. Supports **multi-pass** immediate mode: a widget (e.g. `Grid`)
can `request_discard` to size on an early pass and place on a later one, hiding
first-frame jitter ([egui docs](https://docs.rs/egui/latest/egui/),
[DeepWiki overview](https://deepwiki.com/emilk/egui/1-overview)). **Lesson:** the
clean `Shape → Tessellator → Mesh` boundary is a better factoring than our
`DrawList::push_*` (which bakes tessellation into the widget); and "multi-pass IM"
solves the measure-before-place problem without going fully retained.

**Nuklear (C).** Single-header ANSI-C, public-domain, **zero dependencies and no
default allocations in the build loop**; input goes in as state, output comes out as
*draw commands describing primitive shapes* ([repo](https://github.com/Immediate-Mode-UI/Nuklear)).
**Lesson:** a command-buffer output (primitives, not pre-tessellated vertices) is the
most portable, most cacheable IR — and it's trivially diffable for damage tracking.

### 3.2 Layout & compiled (C, Rust, C++)

**Clay (C).** ~5,300 LOC single header. Immediate-mode *layout*: it recomputes the
entire flexbox layout every frame from a **`Clay_Arena` bump allocator that is reset
at `Clay_BeginLayout()`** and emits a render-command array the caller draws
([repo](https://github.com/nicbarker/clay),
[Simon Willison's notes](https://simonwillison.net/2024/Dec/21/clay-ui-library/)).
**Lesson:** per-frame bump allocation makes "rebuild everything" cheap enough that you
don't *need* retained state for correctness — only for damage tracking. This is the
direct antidote to our per-widget `String`/`Signal` allocations (§4.2).

**Slint (Rust).** A declarative `.slint` markup compiled **ahead of time** to native
Rust/C++/JS. The runtime is <300 KiB, has a **reactive property system**, and lays out
a component's elements/items/properties **in a single contiguous memory region** to
cut allocations; renderers are pluggable (Skia / femtovg-GL / software)
([slint.dev](https://slint.dev/), [GitHub](https://github.com/slint-ui/slint)).
**Lesson:** compiling UI structure to data + packing a subtree into one allocation is
the logical endgame; even without a DSL we can pack a widget subtree into one arena
block and drive updates off the property/epoch system.

**Yoga (C++).** Meta's embeddable flexbox engine (C++20 core, C API,
`YGNodeCalculateLayout`). Its headline optimizations are **caching expensive
measurements (text) so they run once** and **recomputing layout only for nodes that
changed** ([Engineering@Meta](https://engineering.fb.com/2016/12/07/android/yoga-a-cross-platform-layout-engine/),
[DeepWiki](https://deepwiki.com/facebook/yoga)). **Lesson:** our `measure`/`arrange`
already mirrors Yoga's two-phase model — add Yoga's *measurement cache* keyed by
`(node, constraint)` and dirty-subtree skipping.

### 3.3 Declarative / retained (Dart, Swift, JS, Kotlin)

**Flutter (Dart).** Three trees: immutable **Widget** (config) → mutable **Element**
(lifecycle/state, reused across rebuilds) → **RenderObject** (single-pass
constraints-down/sizes-up layout + paint). `RepaintBoundary` composites a subtree to
its own layer so only that layer re-rasterizes
([Inside Flutter](https://docs.flutter.dev/resources/inside-flutter)).
**Lesson:** separating *config* from *persistent element* from *render node* is what
lets you rebuild cheaply (diff Elements) **and** repaint cheaply (layer caching). Our
`Widget` conflates all three.

**SwiftUI (Swift).** Views are value types diffed by **identity, not type**; a private
**AttributeGraph** tracks which view bodies read which state, so a state change
invalidates *only* the dependent attributes ([Untangling the AttributeGraph](https://rensbr.eu/blog/swiftui-attribute-graph/),
[DoorDash on identity](https://careersatdoordash.com/blog/how-the-swiftui-view-lifecycle-and-identity-work/)).
**Lesson:** dependency-precise invalidation (not "rebuild the world") is the high bar;
our `Signal` subscribers list is the right *idea* but the read path is too expensive
(§4.5) and `map` is unimplemented.

**React / React Native (JS).** Virtual DOM diffed by an O(n) heuristic; **Fiber**
rewrote the reconciler as an interruptible, linked-list **work loop** (`workLoop` →
`performUnitOfWork`) that can pause/resume/prioritize across frames
([legacy reconciliation docs](https://legacy.reactjs.org/docs/reconciliation.html),
[Velotio on Fiber](https://www.velotio.com/engineering-blog/react-fiber-algorithm)).
**Lesson:** for big trees (e.g. a 10k-row outliner) an interruptible build loop keeps
the frame budget; pair with our existing `VirtualList` windowing.

**Jetpack Compose (Kotlin).** State lives in a **slot table** — a **gap buffer**
(flat `IntArray` with a movable gap; get/insert/delete are O(1), moving the gap is
O(distance)). Every composable is a *group*; **positional memoization** (`remember`)
stores results per call-site so unchanged subtrees are skipped on recomposition
([Leland Richardson, under the hood pt.2](https://medium.com/androiddevelopers/under-the-hood-of-jetpack-compose-part-2-of-2-37b2c20c6cdd),
[gap buffers in Compose](https://proandroiddev.com/understanding-gap-buffers-in-jetpack-compose-the-60-year-old-algorithm-powering-modern-android-ui-a07ca2013e64)).
**Lesson:** a positional/call-site cache is a cleaner identity scheme than our
`WidgetIdPath` `String` hashing — it's an index into a flat array, not a hashed string.

### 3.4 GPU scene / native (Rust, C++)

**WebRender (Rust, Servo/Firefox).** Retained, multithreaded; consumes a post-layout
display list and **batches primitives by shared texture/state** (the primitive cache
groups items in batches of ~512), running the backend on a worker thread
([Servo wiki](https://github.com/servo/servo/wiki/Webrender-Overview),
[repo](https://github.com/servo/webrender)). **Lesson:** sort/batch the drawlist by
(pipeline, texture) before upload; our drawlist is already a single VB/IB but isn't
sorted or batched by state, and the atlas already gives us a shared texture to batch on.

**Qt Quick (C++).** A retained **scene graph** traversed and rendered via
GL/Vulkan/Metal/D3D. Because the full primitive set is known before drawing, it
**batches draw calls and retains geometry on the GPU** — the docs' example collapses
backgrounds+icons+text into **3 draw calls**; render runs on a dedicated thread
([Qt 6 scene graph](https://doc.qt.io/qt-6/qtquick-visualcanvas-scenegraph.html)).
**Lesson:** retaining geometry on the GPU and only re-uploading dirty buffers is the
win our per-frame full re-upload (`RingBuffer::upload`) leaves on the table.

### 3.5 Summary matrix

| Impl | Lang | Paradigm | Layout | State/identity | Allocation model |
|---|---|---|---|---|---|
| Dear ImGui | C++ | Immediate | per-frame | ID-stack hash | persistent buffers, no per-widget heap |
| egui | Rust | Immediate (multi-pass) | per-frame | `Id` hash in `Context` | reused, tessellate→mesh |
| Nuklear | C | Immediate | per-frame | ID-based | none in build loop |
| Clay | C | Immediate *layout* | per-frame flexbox | element ids | **bump arena, reset/frame** |
| Slint | Rust | Compiled/declarative | retained, reactive | compiled tree | **single region per component** |
| Yoga | C++ | Layout engine | retained, **cached** | node tree | per-node, cached measurements |
| Flutter | Dart | Retained/declarative | 1-pass constraints | **3 trees**, Element reuse | Element/RenderObject reuse + layer cache |
| SwiftUI | Swift | Declarative | retained | **identity + AttributeGraph** | value types, precise invalidation |
| React Fiber | JS | Declarative | n/a (DOM) | VDOM diff + keys | **interruptible work loop** |
| Compose | Kotlin | Declarative | retained | **slot table / gap buffer** | positional memoization |
| WebRender | Rust | Retained GPU | post-layout list | scene resources | **batch by texture/state (×512)** |
| Qt Quick | C++ | Retained scene graph | retained | node tree | **retain geometry on GPU, batch** |
| **this engine** | Rust | Retained **+** IM (dual) | 2-phase measure/arrange | `WidgetIdPath` **String** | **`String`+`Signal` per widget/frame** |

## 4. Assembly deep-dives

All snippets live in [`docs/gui_research/asm/`](docs/gui_research/asm/); regenerate with
`generate.sh`. Flags: `rustc -O -C opt-level=3 -C target-cpu=x86-64-v3` (Intel syntax).
The dispatch listings are identical on godbolt `r1940` (rustc 1.94.0) and were
mirrored in C++ on `clang2010`.

### 4.1 Dispatch: enum vs `dyn` vtable vs `fn` pointer — *validates the engine's refactor*

Source: [`exp1_dispatch.rs`](docs/gui_research/asm/exp1_dispatch.rs). Single-call form:

```asm
; dispatch_enum  — the match is inlined to branch + compute, no indirection
dispatch_enum:
        mov     eax, dword ptr [rdi]        ; load discriminant
        vmovss  xmm4, dword ptr [rdi + 4]   ; load gap
        test    eax, eax
        je      .LBB1_4
        ...
        vmulss / vaddss ...                 ; compute Size in registers
        ret
; dispatch_dyn — load fn from vtable slot, tail-jump
dispatch_dyn:
        mov     rax, qword ptr [rsi + 24]   ; vtable[3] -> measure
        mov     esi, edx
        jmp     rax
```

A single virtual call is "just" one extra load + indirect jump. The real cost shows up
**in a hot loop over a homogeneous run** (the per-frame layout pass):

```asm
; solve_many_enum — register-only loop; the *8 constant is hoisted (.LCPI4_0 = 8.0f)
.LBB4_4:
        mov     ecx, dword ptr [rdi + rax]  ; load tag
        test    ecx, ecx                    ; cheap, perfectly predicted branch
        je      .LBB4_8
        ...
        vaddss  xmm1, xmm1, xmm4            ; accumulate, no call, no spill
        add     rax, 8
        cmp     rsi, rax
        je      .LBB4_2

; solve_many_dyn — spills around an indirect call EVERY iteration
.LBB3_4:
        vmovss  dword ptr [rsp + 20], xmm2  ; spill accumulator (call clobbers xmm)
        mov     rdi, qword ptr [r14]
        mov     rax, qword ptr [r14 + 8]    ; load vtable ptr
        mov     esi, 8
        vmovss  xmm0, dword ptr [rsp + 12]  ; reload args from stack
        vmovss  xmm1, dword ptr [rsp + 16]
        call    qword ptr [rax + 24]        ; indirect call -> no inlining, BTB pressure
        vmovss  xmm2, dword ptr [rsp + 20]  ; reload accumulator
        vaddss  xmm2, xmm2, xmm0
        add     r14, 16
        cmp     r14, rbx
        jne     .LBB3_4
```

**The same pattern reproduces in C++** ([`clang2010`, godbolt](https://godbolt.org/)):
a `switch` inlines, while `virtual` becomes `mov rax,[rdi]; mov rax,[rax]; jmp rax`,
and the homogeneous loop spills to `[rsp]` and does `call qword ptr [rax]` per element.

**Takeaway.** The engine's `LayoutDispatch` enum and bare-`fn`-pointer choices
(`ui_core/layout.rs`, `widget.rs`) are *confirmed correct*. The enum loop keeps the
accumulator in `xmm1`, hoists loop-invariants, and stays branch-predictable; the
`Box<dyn>` form forces a stack frame, per-iteration reloads, and an indirect call that
defeats inlining and pressures the branch-target buffer. **Rule for the redesign:** no
`Box<dyn Widget>`/`Box<dyn LayoutSolver>` anywhere on the per-frame path — closed enums
+ `fn` pointers only. (`enum_dispatch`-style designs measure ~10–12× faster than boxed
trait objects in the wild — [enum_dispatch](https://docs.rs/enum_dispatch/),
[Rust dispatch explained](https://www.somethingsblog.com/2025/04/20/rust-dispatch-explained-when-enums-beat-dyn-trait/).)

### 4.2 Per-frame bump arena (Clay-style) vs the allocator we use today

Source: [`exp2_arena.rs`](docs/gui_research/asm/exp2_arena.rs).

```asm
bump_reset:                       ; Clay_BeginLayout(): wipe the frame in ONE store
        mov     qword ptr [rdi + 8], 0
        ret
bump_alloc16:                     ; align + bump + bounds check, no call
        mov     rax, qword ptr [rdi + 8]
        add     rax, 7
        and     rax, -8
        lea     rcx, [rax + 16]
        cmp     rcx, qword ptr [rdi + 16]
        jbe     .LBB2_2
        xor     eax, eax          ; overflow -> null
        ret
```

By contrast `alloc_string` (what `to_owned()`/`Signal::new` boil down to) contains
**4 `call` sites** into `__rust_alloc`/realloc plus a `memcpy`. Our IM builder pays
this *twice per widget per frame* (`WidgetIdPath…to_string()` and
`Signal::new(text.to_owned())` in `ui_widgets/immediate.rs`).

**Takeaway.** Route all transient per-frame build data through a bump arena that
`reset`s at frame start (one store). Widget *identity* should be a call-site
index/hash (Compose-style, §3.3), not a freshly allocated `String` path.

### 4.3 Hot drawlist: AoS quad emission and the 20-byte-stride trap

Source: [`exp3_drawlist.rs`](docs/gui_research/asm/exp3_drawlist.rs). The fast path of
`push_rect` (faithful to `ui_render/drawlist.rs`) is straight inline stores — good,
no per-call function overhead — but note the offsets:

```asm
        vmovlpd qword ptr [rax + 4*r8],      xmm3   ; pos  (8 bytes)
        mov     qword ptr [rax + 4*r8 + 8],  0      ; uv   (8 bytes, zero)
        mov     dword ptr [rax + 4*r8 + 16], ecx    ; color(4 bytes)  -> 20-byte stride
        mov     qword ptr [rax + 4*r8 + 20], r13    ; next vertex starts at +20 (misaligned)
```

The `[u8;4]` color packed inline at offset 16 makes the vertex **20 bytes**. Vertices
land at byte offsets 0, 20, 40, 60 — never 16/32-aligned — so the compiler cannot fuse
the four vertices of a quad (or a run of quads) into wide `vmovaps` SIMD stores; each
field is written individually.

**Takeaway.** Two complementary options for the redesign:
(a) keep AoS but pad/realign the vertex (or split color into the upload step) so quad
emission can vectorize; or (b) an **SoA** drawlist (separate `pos`/`uv`/packed-`color`
streams, see `push_rect_soa`) which the compiler vectorizes and which gives the GPU a
tight, cache-friendly stride. Either way, **batch by (pipeline, texture)** before
upload (WebRender §3.4) and only re-upload dirty ranges (Qt Quick §3.4) instead of the
whole buffer each frame.

### 4.4 Flex distribution: branchy `match` (scalar) vs branchless (vectorized)

Source: [`exp4_layout.rs`](docs/gui_research/asm/exp4_layout.rs). The natural
per-child `match Sizing { Fixed/Hug/Fill }` compiles to a **scalar** loop (0 packed
adds). Pre-flattening the sizing decision into a `{fixed_px, is_fill∈{0,1}}` stream
lets LLVM **auto-vectorize and 8× unroll**:

```asm
; distribute_branchless inner loop (9× vaddps total, unrolled)
.LBB0_8:
        vmovsd  xmm2, qword ptr [rax]
        vaddps  xmm1, xmm1, xmm2          ; packed add: fixed_px and is_fill at once
        vmovsd  xmm2, qword ptr [rax + 8]
        vaddps  xmm1, xmm1, xmm2
        ...                               ; ×8 then horizontal-reduce
```

Measured property: branchy = **0** `vaddps` (scalar `vaddss` only); branchless = **9**
`vaddps`. **Takeaway.** Keep the ergonomic `Sizing` enum at the *API* layer, but lower
it once per dirty subtree into a flat SoA the measure pass sums with SIMD — the same
"compile structure into data" trick Slint uses.

### 4.5 Reactivity: `Rc<RefCell>` `Signal::get` vs an epoch counter

Source: [`exp5_reactivity.rs`](docs/gui_research/asm/exp5_reactivity.rs). The engine's
`Signal::get` (`self.inner.borrow().value.clone()`) compiles to:

```asm
signal_get_f32:
        mov     rax, qword ptr [rdi]                 ; deref Rc (pointer chase)
        movabs  rcx, 9223372036854775807             ; isize::MAX
        cmp     qword ptr [rax + 16], rcx            ; borrow-flag check
        jae     .LBB3_2                              ; -> panic path if mutably borrowed
        vmovss  xmm0, dword ptr [rax + 24]          ; finally, load the value
        ret
.LBB3_2:
        call    core::cell::panic_already_mutably_borrowed
```

An epoch read is one instruction:

```asm
epoch_read:
        vmovss  xmm0, dword ptr [rdi + 8]            ; done.
```

And a dirty-scan over many widgets (`scan_dirty_epoch`, `v != last`) is a clean
branch-light loop. **Takeaway.** Reads dominate UI (every widget reads its bound state
each frame). Replace the hot read path with a **version/epoch** model
(Compose/SwiftUI, §3.3): store `value: T` inline + a `u64 version`; a consumer caches
`last_seen` and recomputes only when `version != last_seen`. Keep `Rc<RefCell>`-style
sharing only for genuinely shared, rarely-read cells — and finish or delete the
stubbed `Signal::map`.

### 4.6 Glyph emission: the UTF-8 `chars()` tax

Source: [`exp6_glyph.rs`](docs/gui_research/asm/exp6_glyph.rs). The faithful
`push_text` (iterating `text.chars()`) generates **~348** asm lines; an ASCII byte-path
variant generates **~158** — the UTF-8 decoder is roughly half the function. For UI
labels (overwhelmingly ASCII) the decode is pure overhead.

**Takeaway.** Add an ASCII fast path (iterate bytes, fall back to `chars()` only when a
byte ≥ 0x80 appears), and cache the shaped run (glyph quads) per `(string, size)` so
static labels aren't re-shaped every frame — this is Yoga's "measure text once" lesson
(§3.2) applied to glyph quads.

## 5. Synthesis — patterns worth stealing

1. **Closed-set dispatch only on the frame path** (enum + `fn` ptr). *Evidence:* §4.1.
   *Already done* in `LayoutDispatch`/`WidgetKind` — enforce it everywhere, forbid
   `Box<dyn>` in widgets/layout/draw.
2. **Per-frame bump arena for transient build data; identity by call-site index.**
   Clay + Compose. *Evidence:* §4.2. *Target:* `ui_widgets/immediate.rs`.
3. **Three-role separation: config → element(state) → render node.** Flutter/React.
   Lets you diff cheaply *and* repaint cheaply. *Target:* split `Widget` (`ui_core/widget.rs`).
4. **Cached, dirty-tracked, SIMD-friendly layout.** Yoga + §4.4. Cache measurements by
   `(node, constraint)`; lower `Sizing` to a flat SoA per dirty subtree. *Target:*
   `ui_core/layout.rs`, `ui_manager/layout.rs`.
5. **Epoch/version reactivity for reads; precise invalidation for writes.**
   Compose/SwiftUI + §4.5. *Target:* `ui_core/signal.rs`.
6. **Retained GPU geometry + damage regions + state batching.** Flutter
   `RepaintBoundary`, WebRender ×512 batches, Qt Quick "3 draw calls". *Evidence:*
   §4.3. *Target:* `ui_render/{drawlist,renderer,vertex}.rs`.
7. **Tessellation as a distinct stage** (egui `Shape → Tessellator → Mesh`) and an
   ASCII/text-shaping cache (§4.6). *Target:* `ui_render/`.
8. **Interruptible build for huge trees** (React Fiber) layered onto the existing
   `VirtualList` windowing. *Target:* `ui_core/widget.rs` (`VirtualListState`).

## 6. Full redesign proposal

A **hybrid retained-tree + immediate-build** UI, unified into one module, keeping every
fast idiom the engine already has and closing the gaps from §2e.

### 6.1 Module consolidation
Today `src/render/ui_core/` and `src/resource_manager/ui_manager/` are two parallel
widget/layout/draw stacks. Collapse to **one** `src/render/ui/` with submodules
`tree`, `build` (immediate API), `layout`, `paint`, `text`, `react`, `input`, `theme`.
`ui_manager`'s per-widget files become *state structs* on `WidgetKind`; its `DrawList`
merges into `ui_render`. This removes the duplicate `DrawList`/`UiVertex`/layout code
and a whole class of "which one is canonical?" bugs.

### 6.2 Core data model — three roles, all enum-dispatched
- **Config (transient):** produced by the immediate `build` API into a per-frame bump
  arena (§4.2); never heap-allocates per widget. Identity = a call-site key (parent
  hash ⊕ a `&'static str` site label ⊕ optional loop index), an integer — *not* a
  `String` path (replaces `WidgetIdPath::to_string()`).
- **Element (retained):** `Widget` keeps `id`, `kind: WidgetKind`, `children`,
  `dirty: u8`, cached `rect`, `constraint`, `layout_solver: LayoutDispatch`, and now a
  **`focusable: bool` + focus/tab-order** field. State (`ButtonState`, …) stays on
  `WidgetKind`. Reused across frames by identity (Flutter Element reuse).
- **Render node (retained GPU):** the tessellated mesh + clip + texture for a subtree,
  cached behind a **damage flag** (Flutter `RepaintBoundary`).

All three use closed enums / `fn` pointers — *no `Box<dyn>` on the frame path* (§4.1,§5.1).

### 6.3 Layout — cached two-pass, SIMD lowering
Keep `measure`/`arrange` and `LayoutDispatch`. Add: (a) a **measurement cache** keyed
by `(WidgetId, Constraint)` reused via `LayoutContext` (Yoga, §3.2); (b) **dirty-subtree
skipping** driven by `DirtyFlags::LAYOUT`; (c) per-dirty-subtree **lowering of
`Sizing` to a flat `{fixed_px, is_fill}` SoA** so the distribution pass vectorizes
(§4.4). Unify the two flex models (`ui_core` Row/Column + `ui_manager` Fill/Fixed/Hug)
into one.

### 6.4 Rendering — damage-driven, batched, retained geometry
- Introduce a tessellation stage (`Shape → Mesh`, egui §3.1) so widgets emit *shapes*,
  not vertices.
- **Batch** the drawlist by `(pipeline, texture/atlas)` before upload (WebRender §3.4).
- Address the **20-byte stride** (§4.3): pad/realign `UiVertex` or move to SoA so quad
  emission vectorizes and GPU stride is clean.
- Re-upload **only dirty ranges** of the `RingBuffer` instead of the whole buffer
  every frame; cache subtree meshes behind damage flags (Qt Quick / Flutter §3.4).

### 6.5 Reactivity — epoch reads, precise writes
Replace the `Signal::get` hot path (§4.5) with `Versioned<T> { value: T, version: u64 }`:
reads are a single load; consumers store `last_seen` and recompute only on
`version != last_seen`. Keep a subscriber list for write-side invalidation (mark
dependent widgets' `dirty`), giving SwiftUI-style precise invalidation. Implement or
remove the stubbed `Signal::map`.

### 6.6 Capabilities mapped to gaps (§2e)
- **Focus & keyboard nav:** focus ring in the manager (`Option<WidgetId>` focused),
  Tab/Shift-Tab order from `focusable` + tree order; route `UiInputState.chars` to the
  focused `TextEdit`. (`ui_core/manager.rs`, `ui_manager/input.rs`.)
- **Scroll containers:** render the existing `VirtualListState` — clip + offset +
  `visible_range()` (already implemented) → only build/tessellate visible items
  (`ui_core/widget.rs`).
- **Multi-line TextEdit:** line-broken layout + cursor/selection + the text-shaping
  cache from §4.6 (`ui_render/text`).
- **Animation/transition:** a small timeline driving `Versioned` properties; dirties
  only animated subtrees per frame.
- **Docking/windowing:** a `Panel`/dock-node tree over the existing `Panel` system.

### 6.7 What explicitly stays (already optimal)
`LayoutDispatch` enum dispatch; bare `fn` pointers in `VirtualList`/`PropertyGrid`;
`Arc<str>` option interning; `ThinVec` everywhere; `dirty: u8` flags; the
ring-buffered host-visible Vulkan upload; the `fontdue` dynamic atlas.

## 7. Migration roadmap

Each phase is independently shippable, behind the existing harness, and extends
`benches/ui_core.rs` so regressions are caught immediately.

| Phase | Change | Bench to add (`benches/ui_core.rs`) | Risk |
|---|---|---|---|
| 0 | **Lock in §4.1**: add a `#![deny]`-style review rule / test that no `Box<dyn>` appears on widget/layout/draw paths. | `solve_many` enum-vs-dyn micro (guards the win) | none |
| 1 | **Epoch reactivity** (§6.5): add `Versioned<T>`, migrate `LabelState`/`SliderState` reads; finish/remove `Signal::map`. | `Versioned::get` vs `Signal::get` | low |
| 2 | **Bump arena for IM build** (§6.2): kill per-widget `String` path + `to_owned`; identity = call-site key. | `UiBuilder` rebuild of N widgets (alloc count → 0) | low |
| 3 | **Cached + SIMD layout** (§6.3): measurement cache, dirty-subtree skip, `Sizing` SoA lowering. | `measure/arrange` 1k-widget tree, dirty vs clean | med |
| 4 | **Drawlist batching + vertex realign + dirty-range upload** (§6.4). | `push_rects_bulk` (vectorized), batch-by-texture | med |
| 5 | **Tessellation stage + ASCII/text-shaping cache** (§4.6, §6.4). | `push_text` vs cached run | med |
| 6 | **Module consolidation** (§6.1): merge `ui_core` + `ui_manager`. | n/a (compile + existing tests) | high (mechanical) |
| 7 | **Capabilities** (§6.6): focus/keyboard nav, scroll containers, multi-line TextEdit, animation, docking. | per-feature | feature-by-feature |

**End-to-end verification.** After each phase: `cargo build --workspace`,
`cargo test` (UI unit tests in `ui_core/{layout,signal}.rs` already exist),
`cargo bench --bench ui_core`, and a manual smoke via the `editor` binary
(`src/bin/editor.rs`). Re-run `bash docs/gui_research/asm/generate.sh` if any snippet's
corresponding engine code changes, and confirm the embedded listings still hold.
